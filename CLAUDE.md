# Sawit Fabricator — Project Context

A 2D turn-based grid tactics puzzle in Unity, themed as **Corrupting Tech vs. Botanical Seed**. The board is
the cellular matrix of a seed incubating inside a high-tech **Fabricator Machine**. The player has
injected a nanite-glitch strain, the **Tech Bug**, to overwrite the seed's genetic code. The player clicks
the Tech Bug and picks one of up to 8 directions, and it slides until something stops it. Corrupting every
**Seed Embryo** wins. **Root Sentinels** grow bramble roots that wall off tiles. Clickable tiles (seed-coat
gates, sap routers, injector glands) change the board.

Theme names are used in docs and art only. **The code keeps its original class names** (renaming
MonoBehaviours would break prefab references), so map theme → class with this table:

| Theme name                         | Old theme name  | Class                        |
|------------------------------------|-----------------|------------------------------|
| Tech Bug (Cyber-Infection Core)    | Cancer Cell     | `BasePlayer` (`Player1`)     |
| Seed Embryo (Flora Nucleus)        | Core Cell       | `CoreCell : BaseUnit`        |
| Root Sentinel                      | Defensive Cell  | `BlockingEnemy : BaseEnemy` (grows `VineSegment` vines) |
| Bramble roots / thorny vines       | Vines           | `VineSegment`                |
| Seed-coat gate                     | Membrane gate   | `CellWallGateTile`           |
| Sap router                         | Deflector valve | `DeflectorValveTile`         |
| Injector gland                     | Chemical valve  | `ChemicalValveTile` (retracts roots) |
| Seed matrix tile                   | Cytoplasm       | `GrassTile`                  |
| Lignin wall                        | Cellulose wall  | `WallTile`                   |
| Resin snare                        | —               | `StopTile`                   |
| Pollen Drifter (passive)           | —               | `MovingCell : BaseEnemy` (`hostile` off) |
| Seed Burr (hostile)                | —               | `MovingCell : BaseEnemy` (`hostile` on) |

Some code and asset names still carry the old theme (`cancer_cell.png`,
`PlayerSkull`, "Level 2 Infection Route"). Leave them alone unless you rename them inside Unity.

## Tech

- **Unity 6000.6.5f1** (Unity 6.6), **URP 2D** renderer, new **Input System** (`InputSystemUIInputModule`)
- Clicks come through the EventSystem: `Physics2DRaycaster` on the camera, `BoxCollider2D` on clickables,
  and `IPointer*Handler` interfaces. There's no `Update()` polling of the mouse.
- No asmdefs for game code. Scripts compile into `Assembly-CSharp`, and `Assets/Editor/` compiles into
  `Assembly-CSharp-Editor`.
- Main scene: `Assets/Scenes/LevelScene.unity`, the only enabled build scene. `SampleScene` is left over
  from the template and disabled.

## Game flow

`GameManager.ChangeState(GameState)` drives the game:

```
Start → GenerateGrid → SpawnPlayerUnit → SpawnEnemyUnit → PlayerTurn ──→ Win / Lose
         (GridManager)   (UnitManager)     (UnitManager:      (moves and
                                            enemies + cores)   clicks repeat)
```

- The player keeps moving during `PlayerTurn`. After each slide the **Moving Cells** take their turn in
  `EnemyTurn` (passive cells, then hostile ones), then it's `PlayerTurn` again. Without Moving Cells the
  state never leaves `PlayerTurn`.
- **Win:** a move corrupts the last Seed Embryo (`UnitManager.ResolveOutcome(capturedCoreCell: true)`).
- **Lose (hazard):** the last Tech Bug slides into thorny roots or a hostile Moving Cell, or a hostile Moving Cell
  steps onto it, and it's destroyed (`DestroyPlayer`).
- **Lose (energy):** the level has a move limit, energy hits 0 and the level isn't won. Checked after the win
  check, so corrupting the last embryo with the last move still wins. Energy and stuck losses also apply to a
  level with no Seed Embryos at all (it can't be won, but it must still be losable).
- **Lose (stuck):** the level isn't won and no Tech Bug has any safe slide in any direction. With
  `UnitManager.interactablesPreventLose` on (the default), it's also required that no gate, router or
  gland can be clicked, since clicking one might open a path. Turn it off for the strict rule.
- The outcome is checked after every finished slide and after every interactable click (`OnBoardChanged`).
- **Turns:** `UnitManager.SlideFinished` (static event) fires once per finished slide, after win/lose is
  resolved. Timed effects (roots retracted by an injector gland) count these.
- `GameManager` Win/Lose handlers clear the selection, log, and invoke the `onWin`/`onLose` UnityEvents.
  The static `StateChanged` event fires on every state change. `RestartLevel()` reloads the scene for a Retry button.
- Input stops automatically once the state leaves `PlayerTurn`, because tiles and arrows check for it.

## Core systems

### Grid (`GridManager`)
- Tiles are stored in `Dictionary<Vector2, Tile>`, keyed by integer world position (tile (x, y) sits at
  world (x, y)). `AllTiles` lists every tile.
- `GetTileAtPosition(Vector2)` returns null when the position is off the board, which acts as the board edge.
- Camera is centred on the board after generation.
- **With a `LevelData` assigned** (the `level` field), the size and the tile in each cell come from the level.
  Without one, it falls back to `width`/`height`/`tilePrefab`, and units spawn randomly on each half of the board.
- LevelScene currently has **Level 2 Infection Route** assigned.
- **Fabricator frame:** when `frameSprite` is set (LevelScene uses `fabricator_frame`), `BuildFrame()` adds a
  `Sliced` SpriteRenderer sized to the board plus the sprite's 9-slice border on each side, so the border's inner
  edge hugs the tiles (TileRender order −5). The sprite's border (192 px of 512) must be set in its import settings.

### Tiles (`Tile`)
- `walkable => isWalkable && occupiedUnit == null && !isBlocked`. `isWalkable` is protected, so
  subclasses (gates) can change it.
- `SetUnit(unit)` moves a unit onto the tile and clears its previous tile.
- `SetSelected(bool)` keeps the highlight on for the selected unit's tile.
- Clicking a tile: a Tech Bug on it → select it; else if `CanInteract` → `Interact()`, then
  `UnitManager.OnBoardChanged()`; otherwise deselect.
- Blocking: `AddBlocker`/`RemoveBlocker` track a `HashSet<BlockingEnemy>`, so a tile stays blocked until
  **every** blocker retracts. The tile only tracks state; root visuals belong to the `BlockingEnemy`.
  `IsHazardous` is true if any blocker on it is hazardous; `IsWalkableTerrain` ignores units and roots.
- `CreateOverlay(name, sprite, color, orderOffset)` adds a child sprite on the tile's sorting layer.

### Camera (`CameraController`, on Main Camera)
- Middle/right-mouse drag pans 1:1 with the cursor (after `dragThresholdPixels`), WASD/arrows pan, and the
  scroll wheel zooms toward the cursor with damping (`minOrthographicSize`..`maxOrthographicSize`).
- Clamped so the view stays within the board (`GridManager.Width`/`Height`) plus `boundsPadding`. If the view
  is bigger than that, it's centred. Input is ignored while the app is unfocused; scroll zoom and edge
  scrolling are ignored while the cursor is outside the game view.
- Edge scrolling (`enableEdgeScrolling`, `edgeScrollMarginPixels`, `edgeScrollSpeed` in world units/s) is skipped
  while a pan button is held or a focus move runs.
- **Space** (`FocusOnPlayer()`) eases the view onto the selected Tech Bug (else any `BasePlayer`) over
  `recenterDuration`, clamped to the bounds. A pan press or WASD/arrow input cancels it.
- Board clicks fire on **pointer down**, so `Tile` and `MoveArrow` only react to the left button and ignore
  presses while `CameraController.IsPanning`.

### Units
- `BaseUnit` has `UnitName`, `OccupiedTile`, `Faction`.
- **Check units by type (`is BasePlayer`, `is CoreCell`, `is BlockingEnemy` / `is BaseEnemy`), not by the
  `Faction` field.** Prefab faction values have been wrong before (EnemySawit was set to Player).
- `ScriptableUnit` (in `Resources/Units`) pairs a `Faction` with a `UnitPrefab`. Level placements and
  random spawning both refer to these assets. Random spawning picks by prefab type.
- **`CellIdleAnimator`** (on PlayerSkull, CoreCell, EnemyBlocker and its Thorny variant): sine "breathing"
  scale (`scaleFrequency`, `scaleAmplitude`, optional `squashAndStretch`) and Z sway (`rotationFrequency`,
  `rotationAngleMax`), random phases per cell. It animates relative to the scale/rotation captured in
  `OnEnable` and restores them in `OnDisable`, so **disable it before animating the unit's transform
  yourself** (`DestroyPlayer` does). Slides only move position, so they don't conflict.

### Energy (move limit) (`UnitManager`, `LevelData`, `PlayerEnergyFlasher`, `EnergyCell`)
- Per level: `LevelData.initialMoves` (default 3; **0 = unlimited**) and `maxMoves` (cap, default 10).
  Levels 1–5 and Level Test are set to 0 (they were designed without a limit). No LevelData = unlimited.
- `UnitManager.InitEnergy` runs at the start of `SpawnPlayers` (before the players exist). Energy is one pool
  shared by every Tech Bug. `CurrentMoves`, `MaxMoves` (0 when unlimited), `MovesLimited`.
- Each finished slide calls `SpendMove(restored)`: −1, then + the captured unit's `MovesRestoredOnCapture`,
  clamped to `0..maxMoves`. Clicking interactables is free. Hazard deaths don't spend.
- **Every unit** has a serialized `movesRestoredOnCapture` on `BaseUnit` (default 0; read via
  `MovesRestoredOnCapture`). Prefab values: CoreCell **3**, EnergyCell **3**, everything else 0 (set it on any
  enemy prefab, e.g. a Root Sentinel, to make capturing it recharge).
- Per-level override: `LevelData.UnitPlacement.overrideMovesRestored` + `movesRestoredOnCapture` →
  `SetMovesRestoredOnCapture` when spawning. The painter shows a cyan "+N" badge on units that recharge
  ("*" = overridden for that placement); badges only show in levels with a move limit.
- **`EnergyCell : BaseUnit`**: a capturable Fabricator power capsule that only recharges; it doesn't count
  toward winning. Spawned from LevelData (`SpawnEnemies` → BaseEnemy, CoreCell, then EnergyCell). Prefab
  `Prefabs/Units/Energy/EnergyCell` (scale 0.8, quick idle hum), unit asset `Resources/Units/Energy/EnergyUnit 1`.
  Cyan outline in the level painter.
- Events: `UnitManager.OnMovesChanged(current, max)` on every change (including the initial value), and
  `UnitManager.OnEnergyCritical(current)` whenever energy changes to 1..`lowEnergyThreshold` (default 2).
  A UI energy counter should subscribe to `OnMovesChanged` (no counter UI exists yet).
- **`PlayerEnergyFlasher`** (on PlayerSkull): only changes `SpriteRenderer.color`, so it layers with
  `CellIdleAnimator`. At ≤ `lowMoveThreshold` (default 2) moves it pulses alpha (`pulseMinAlpha`..1,
  `pulseFrequency`); at 1 move it strobes faster toward `criticalTint` with Perlin-noise glitch dropouts
  (`flickerAmount`, `flickerAlpha`). Restores the original colour when energy rises, the level is unlimited,
  or the state leaves PlayerTurn. Reads the current value in `OnEnable`, so late spawns catch up.

### Movement (`UnitManager` + `MoveArrow`)
- Arrows appear on neighbouring tiles for each of the 8 directions where the slide path isn't empty.
- `GetSlidePath(start, direction)` returns every tile passed through; the last one is where the unit ends up:
  - off the board → stop on the current tile
  - an enemy, Seed Embryo or Energy Cell (`IsCapturable`) → stop **on** its tile (capture)
  - a resin snare (`StopTile`, walkable) → enter it and stop **on** it. Starting a move from one is
    unaffected. Prefab `Prefabs/Tiles/Stop Tile` (Base Tile variant, `stop_tile` art); add it as a tile type
    in a LevelData to paint it
  - a friendly unit, non-walkable tile (wall, closed gate) or root-blocked tile → stop **before** it. Roots are
    checked first, so a unit under roots can't be captured through them (capture the Root Sentinel or retract them)
  - thorny (hazardous) roots over walkable terrain, or a hostile Moving Cell → enter the tile and be destroyed (`endsInHazard`); these
    moves still get arrows, tinted red, and don't count as a way out for the lose check
  - a sap router → enter it, then continue in the router's `OutputDirection`. Entering the same
    router with the same heading twice ends the slide, which stops router loops from running forever.
- `SlideAlongPath` animates tile by tile (`moveSpeed`, default 8) so turns at routers are visible, then
  captures and calls `SetUnit`. `FinishTurn` then wins right away on the last Seed Embryo, otherwise runs the
  Moving Cells, then resolves win/lose and fires `SlideFinished`. Input is ignored while `IsBusy` (the whole
  turn, enemy phase included).
- `Capture` removes a Seed Embryo from the count and a Moving Cell from the turn order right away (`Destroy` is
  deferred, and the enemy phase starts the same frame), then destroys the unit.
- `MoveArrow` uses `GeneratedSprites.Triangle` unless `arrowSprite` is set on UnitManager. It must be on
  the **"Units"** sorting layer, or the tiles cover it and catch its clicks.

### Moving Cells (`MovingCell : BaseEnemy`)
- Step **one tile** after every Tech Bug slide (not after gate/router/gland clicks), cycling through
  `moveSequence` (e.g. up, down; any length). Each entry is clamped to -1..1 per axis, so diagonals work and
  `(0,0)` is a deliberate wait. Per-level override: `LevelData.UnitPlacement.overrideMoveSequence` +
  `moveSequence` → `SetMoveSequence` (before Start).
- **Turn order:** Tech Bug → every passive cell (together) → every hostile cell (together) → Tech Bug. Within a group,
  steps are decided in spawn order, so a cell can move into a tile another just left. Run by
  `UnitManager.MoveCells`/`MoveCellGroup`, all moves animated at once over `1 / moveSpeed`.
- **Blocked** (wall, closed gate, roots, any other unit, board edge): the cell waits, but its sequence still advances.
  Moving cells ignore sap routers (they just step onto them).
- **Passive** (`hostile` off): captured on contact either way: the Tech Bug slides onto it, or it steps into the
  Tech Bug (then it's removed and its `MovesRestoredOnCapture` energy is granted via `RestoreMoves`).
- **Hostile** (`hostile` on): never capturable. The Tech Bug sliding into it is destroyed (red arrow, not a way
  out for the stuck check), and a hostile cell stepping onto the Tech Bug takes its tile and destroys it.
- Shows its **next step** as a small triangle on its edge (`indicatorColor`, Units order 2), updated as it advances.
- Register with `UnitManager` in `Start`, unregister in `OnDestroy`.
- Prefabs `Prefabs/Units/Enemies/MovingCell` (Pollen Drifter, `moving_cell` art) and `MovingCell Hostile`
  (Seed Burr, `moving_cell_hostile`), unit assets `EnemyUnit Moving` / `EnemyUnit Moving Hostile`.
- Level painter: amber outline (passive) / red (hostile), a dot on each tile the cell visits over one cycle (ignoring
  blockers), and a warning for an empty sequence.

### Seed Embryos (`CoreCell : BaseUnit`)
- Stationary targets. They register with `UnitManager` in `Start` and unregister in `OnDestroy`.
- `UnitManager.ActiveCoreCellCount` is the number still on the board. A level with none can't be won,
  and the level painter warns about this.
- Spawned from `LevelData` placements (`SpawnEnemies` spawns `BaseEnemy` and then `CoreCell` placements).
  They don't spawn in the random fallback mode.
- Prefab: `Prefabs/Units/Cores/CoreCell` (`core_cell` art). Unit asset:
  `Resources/Units/Cores/CoreUnit 1`.

### Root Sentinels and bramble roots (`BlockingEnemy : BaseEnemy`, `VineSegment`)
- The Root Sentinel is a host that grows **roots** (vines in code) onto the tiles at `blockedTileOffsets`
  (relative to its own tile; default the 4 neighbours). Covered tiles are blocked. A level placement can
  override the offsets via `SetBlockedTileOffsets`, which must be called before `Start`.
- **Building (in `Start`):** a cheapest-path search from the host through the covered tiles gives each tile a
  parent. A diagonal step costs more than two straight ones, so roots run straight and only cut corners when
  they must. Offsets not touching the rest of the root network get a stub pointing toward the host.
- **`VineSegment`** = one tile's piece, a child of the *tile* (so it can animate away after the host dies).
  It draws `stemSprite` (a half stem from the centre to the right edge, rotated toward each connection and
  stretched on diagonals) plus a `tipSprite` (end, pointing away from its parent) or a `knotSprite`
  (corner/branch). Shapes: Root (host tile, under the host sprite), Tip, Straight, Corner, Branch.
  Drawn on TileRender order 1, stems ×1.6 thick, knots/tips ×1.3. Missing sprites fall back to thin bars.
- **State:** roots are out unless toggled off (`SetVinesActive(false)`) or retracted for N turns
  (`RetractForTurns(n)`, counted on `UnitManager.SlideFinished`). Changing state adds/removes the tiles'
  blockers immediately and animates the pieces (grow outward / retract inward, `growDuration`, `growStagger`).
  When a timed retraction runs out, the roots regrow and call `UnitManager.OnBoardChanged()`.
- **Capture:** `OnDestroy` frees every tile and retracts + destroys all its pieces.
- **Thorny** (`hazardous`, uses `hazardStemSprite`): sliding into these brambles destroys the Tech Bug.
- `BlockingEnemy.VinesChanged` (static event) fires on every extend/retract/timer tick.
- **`enemyColor`** (`ChemicalColor`) links it to ColorMatch injector glands and shows a coloured dot on the
  sentinel (Units order 1). Per-level override: `LevelData.UnitPlacement.chemicalColor` → `SetEnemyColor`
  (before Start). `CoveredTiles` lists the tiles its roots cover.
- Prefabs: `EnemyBlocker` (normal) and `EnemyBlocker Thorny` (variant: hazardous, crimson-tinted host),
  unit assets `EnemyUnit Blocker` / `EnemyUnit Thorny Blocker`.

### Interactable tiles (`PlantInteractableTile : Tile`)
- `PlantInteractableTile` turns `Tile`'s `CanInteract`/`Interact()` into `Toggle()` + `RefreshVisual()`,
  and tints the base sprite with `baseColor` in `init`.
- **Seed-coat gate (`CellWallGateTile`):** clicking it toggles `isWalkable` (Open ↔ Closed). `startsOpen`
  sets the starting state. A gate can't close while a unit is on it. Visuals: a hollow frame when open, a
  solid square when closed (`openSprite`/`closedSprite` can replace them).
- **Sap router (`DeflectorValveTile`):** `allowedDirections` is a flags mask (Right 0°, Up 90°, Left 180°,
  Down 270°) and `startAngle` is the starting direction. Clicking it rotates to the next allowed angle. It can
  only be clicked when 2 or more directions are allowed, so a single direction makes a fixed router. The
  output direction is absolute: it doesn't depend on which way the unit came in. Shown as a rotated glyph
  (`arrowSprite`, triangle fallback).
- **Injector gland (`ChemicalValveTile`):** a Fabricator nozzle that floods tiles with a synthetic ingredient,
  making Root Sentinels retract their roots.
  - `mode`: TimedRetract (`retractTurns`, default 2; clicking again restarts the timer) or Toggle
    (retracted until clicked again).
  - `targetMode` (`ChemicalTargetMode`): **AreaRadius** (hosts within `radius` tiles, Chebyshev, so 1 = 3×3),
    **ColorMatch** (hosts whose `EnemyColor` == `valveColor`), **Global** (every Root Sentinel).
  - `CanInteract`: there's a target, or the gland is active (so a Toggle gland can always be switched off).
  - Each gland tracks **its own** active state (Toggle flag, or its own `turnsLeft` counted on
    `SlideFinished`), so two glands hitting the same sentinel don't light each other up.
  - While active: `releasedSprite`, a pulsing **mist** overlay (`mistSprite`, `mistAlpha`, tinted by
    `valveColor`) on the affected tiles (AreaRadius: the whole area; otherwise each target's host + root
    tiles), and an optional `smokePrefab` particle cloud on the gland. Mist fades in and out; smoke stops
    emitting and is destroyed once its puffs have died. Everything is cleaned up when the effect ends.
  - ColorMatch glands show a colour dot matching the dot on the Root Sentinels they affect.
- **`ChemicalColor`** (enum + `ToColor()`): None, Crimson, Azure, Amber, Violet. None = no marker, never
  colour-matched; its mist colour is pale cream.
- Prefabs `Prefabs/Tiles/Gate Tile`, `Gate Tile Closed`, `Deflector Valve Tile`, `Chemical Valve Tile` (Global,
  Timed), `Chemical Valve Area` (radius 1, Timed) and `Chemical Valve Azure` (ColorMatch Azure, Toggle) are
  variants of Base Tile. Add them as tile types in a LevelData to paint them. Smoke FX:
  `Prefabs/FX/Chemical Smoke` (material `Materials/Chemical Smoke`, Sprites/Default + mist texture).

### Level authoring (`LevelData` + `LevelDataEditor`)
- Create one with *Create → Level Data*.
- Holds `width`, `height`, energy (`initialMoves`, `maxMoves`; edited in the painter's **Energy** section,
  which shows a summary), `tileOptions` (tile prefab + painter colour), `cells` (one int per cell,
  `index = y * width + x`, indexing into `tileOptions`), and `units` (position + ScriptableUnit +
  optional overrides: Root Sentinel root offsets and `chemicalColor`, and any unit's `movesRestoredOnCapture`).
- The Inspector painter has:
  - **Tile Types:** rows with a colour picker and prefab field, plus Add and Remove buttons.
  - **Brushes:** one for each tile type, one for each ScriptableUnit in the project, and Erase Unit.
    Outlines: blue for the Tech Bug, green for Seed Embryos, red for enemies.
  - **Grid:** left-click or drag paints, right-click removes a unit. Row 0 is at the bottom.
  - **Wall preview:** tiles a Root Sentinel will wall off are shown on the grid.
  - **Warnings:** no player placed, no Seed Embryo placed, unit on a non-walkable tile, placement with no unit asset.
- Resize with the Width and Height fields, or `LevelData.Resize` in code. Changing `width`/`height`
  directly would scramble the cells.
- Removing a tile type re-maps the cells (`RemoveTileOption`).

## Rendering / sorting layers

Sorting layers, bottom to top: **Default → TileRender → Units**. The sorting layer always outranks the
sorting order, both for drawing and for which object gets a click.

| Thing                           | Layer      | Order |
|---------------------------------|------------|-------|
| Tile sprite                     | TileRender | 0     |
| Tile highlight                  | TileRender | 1     |
| Root segments (stems, knots, tips) | TileRender | 1  |
| Injector mist overlay (z −0.02, over roots) | TileRender | 1 |
| Gate shutter / router glyph / injector nozzle / gland colour dot | TileRender | 2 |
| Injector smoke particles        | TileRender | 3     |
| Root Sentinel colour dot        | Units      | 1     |
| Units (Tech Bug, Seed Embryo, Root Sentinel) | Units | 0 |
| Moving Cell next-step indicator | Units      | 2     |
| Move arrows                     | Units      | 10    |

The Global Light 2D lights TileRender and Units. Sprites on a layer it doesn't light will render black.
The Fabricator frame uses TileRender order −5 for this reason; it never overlaps a tile.

## Conventions & gotchas

- **Unity CLI is connected** (`unity status`). Prefer `unity command` / `script.run` over hand-editing
  `.prefab`/`.unity`/`.asset` YAML. Play mode crawls when the Editor is unfocused; for scripted play tests use
  `unity command editor.playmode.set_run_in_background --enable true`, and turn it off afterwards.

- **Rename or move scripts and assets inside Unity** (or move the `.meta` file with them) so GUIDs and
  prefab references survive.
- **One MonoBehaviour per file, with the file named after the class**, or Unity can't attach it. That's
  why the gate and valve each have their own file.
- **Don't use `using NUnit.Framework;` in runtime scripts.** It compiles in the Editor but breaks player
  builds. Some IDEs add it automatically.
- Positions are rounded (`Mathf.Round`) before dictionary lookups to avoid float mismatches.
- Code style: Allman-ish braces, `PascalCase` public fields on units (`OccupiedTile`), `camelCase`
  private/serialized fields, short comments only where the reason isn't obvious.

## Art direction (Corrupting Tech vs. Botanical Seed)

**Setting:** a seed chamber inside the Fabricator Machine. The board is the seed's cellular matrix seen
through a viewport, framed by machine hardware. Two visual languages that should never blend:

- **Tech (player):** hard edges, geometric hulls, metal/nanite plating, neon cyan + hot magenta circuitry,
  glitch/scanline aura.
- **Botanical (enemies, targets, gates, routers):** soft organic curves, bark, lignin, moss, leaves, sap glow,
  radial symmetry.
- **Injector glands** are the one hybrid: a steel Fabricator nozzle set into the plant tissue.

**Readability rule:** the board is the background, so it stays **pastel and low-contrast**. Units and
interactables carry all the saturation. If a tile competes with a unit for attention, desaturate the tile.

| Element | Look | Key colours |

**Art pipeline:** every sprite is drawn in code in `Art/build_sprites.js`, which writes the SVGs to
`Art/Source/` and renders 512 px PNGs over the existing files in `Assets/Sprites/Cells`, so GUIDs and prefab
references survive. Run it with Node from `Art/` after `npm install @resvg/resvg-js@2.6.2` (don't commit
`node_modules`). Pass sprite names to rebuild only those. Set `PREVIEW=<dir>` to render somewhere else
without touching the project. The board backdrop is shared (`matrixDefs`/`matrixBody`), so tiles and
interactables stay consistent. Thorny Root Sentinels get a crimson tint on the host sprite, which is why
`defensive_cell` uses mid-tones. The camera background is dark gunmetal `#14181E`.

## Art notes

- Sprites in `Assets/Sprites/Cells` are on the prefabs: units at scale 0.85–0.9, tiles on the Square child,
  gate `openSprite`/`closedSprite`, router `arrowSprite`, UnitManager `arrowSprite` (in LevelScene).
- Tints are white so the art shows its own colours. GrassTile's checkerboard uses a light warm offset tint
  (0.95, 0.91, 0.84); a green offset clashes with the amber matrix.
- Roots use `vine_stem` / `vine_stem_thorny` / `vine_knot` / `vine_tip`; the injector gland uses
  `chemical_valve_idle` / `chemical_valve_released`. Same 512 px / 512 PPU setup, SVG sources in Art/Source.
- Because roots draw on TileRender 1, a gate, router or gland under a root draws its own visual (order 2) over it.
- `MoveArrow` is scaled 0.8 because the `move_arrow` art has padding (so it draws at about half a tile).
